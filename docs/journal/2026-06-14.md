# 2026-06-14 - Adopt Jujutsu (jj), colocated, signed at push

## What changed

jj joins the toolchain as the version-control front-end: `brew "jj"` in the
Brewfile, `scripts/configure/jujutsu.sh`, [ARCH-0032](../decisions/ARCH-0032 Multi-agent version control with Jujutsu.md),
and a tldr-pages page at `docs/tldrs/jujutsu.md`. The configure script reads
identity and the signing key from `git config --global` and applies them with
`jj config set --user`, setting `signing.behavior=drop` and `git.sign-on-push=true`.

Why: several agent sessions plus the operator share repos, and a YubiKey gates
every commit. Git's shared index collides across sessions, and per-commit touch
friction pushed work into rare, large commits whose signatures squash-merge
strips anyway. jj removes the index (the working copy is the commit) and defers
signing to one batch at push, so a whole sitting is touch-free and one push
signs everything with a single touch.

Validated on a throwaway forge-cli clone: a sign-on-push commit landed
GitHub-Verified by the signing subkey with one touch, and gitleaks ran as the
pre-push gate (jj fires no git hooks). Entire is unaffected: its capture runs
off Claude Code hooks; only its git-hook commit-linkage is skipped under jj,
moot under squash-merge anyway.

forge-provision is not colocated yet; its tree carries multi-session work that
should land via plain git first. Rollout is per-repo, on clean trees.

The tldr work also corrected the `WriteDocs` skill upstream: its TLDR companion
now specifies the real tldr-pages format instead of a one-pager.
