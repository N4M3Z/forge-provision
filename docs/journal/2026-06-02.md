# 2026-06-02 — Legcord replaces the official Discord desktop app

> Reversed on 2026-06-03 (see that entry and [PROV-0011][p11]). After supply-chain
> research, Legcord was uninstalled in favour of the official Discord app contained
> by Little Snitch. This entry records the day's actual work; the decision did not stand.

[p11]: ../decisions/PROV-0011%20Discord%20official%20app%20with%20Little%20Snitch.md

## Why not the official Discord app

Discord's desktop app bundles native modules and its own telemetry/crash
reporting, neither of which we want running on this machine. The goal: have
Discord available on device without installing that client.

## Options weighed

| Option | Install | Trust surface |
| --- | --- | --- |
| Browser PWA | nothing new | Smallest. Contained in the browser sandbox, zero new trusted code. No global push-to-talk, limited native screenshare audio. |
| Vesktop | `cask "vesktop"` | Open-source Electron client by the Vencord team. Strips Discord telemetry, ships Vencord by default. Larger community (~8k stars), shares maintainers with Vencord. |
| Legcord | `cask "legcord"` | Open-source Electron client. Vanilla by default with opt-in mods (Vencord/Equicord/Shelter). Smaller community (~3.3k stars). |

On macOS the usual headline split (audio screenshare, Wayland) is Linux-only
for both, so it does not separate them here. Privacy posture is equivalent:
both block Discord's telemetry, add none of their own, and still log into a
real Discord account. ToS risk is equal and low in practice for both; the
realistic ban vector is posting mod-revealing screenshots in servers that
enforce, not Discord central.

## Decision: Legcord

Picked [Legcord][LEGCORD] for the lighter vanilla-by-default posture (run the
minimum unless a mod is explicitly enabled) and the preferred UI. The cost is
a smaller review surface than [Vesktop][VESKTOP]; for a personal machine that
trade is acceptable. Vesktop stays on the radar if the smaller community
becomes a maintenance concern.

## Threat model

The concern is the official Discord native client itself (its bundled native
modules and telemetry), not account-token theft. Goal: keep Discord's own
instrumentation off the machine. Legcord serves this directly: it ships none
of Discord's native modules and blocks Discord's telemetry, while being
open-source rather than Discord's code. Caveat recorded for honesty: Legcord
is still an Electron app with normal filesystem/network access, so it is not
OS-sandboxed from the host the way a browser tab is. True host containment
would require the browser/PWA route or a VM; that was not the requirement.

## Change

`manifests/Brewfile` gains `cask "legcord"`. Installs on a fresh machine via
`scripts/install/brew-bundle.sh` (delegates to `brew bundle install`).
`brew bundle` skips it if already present, so the entry is idempotent.

## Install + signature verification (2026-06-02)

`brew install --cask legcord` placed Legcord 1.2.4 at
`/Applications/legcord.app`. The binary verifies as a notarized Developer ID
build, signed by the project maintainer:

```sh
spctl -a -vv /Applications/legcord.app
# accepted — source=Notarized Developer ID
# origin=Developer ID Application: Patryk Zurek (8N66M2567D)

codesign -dv --verbose=4 /Applications/legcord.app
# Identifier=app.legcord.Legcord
# Authority=Developer ID Application: Patryk Zurek (8N66M2567D) → Apple Root CA
# TeamIdentifier=8N66M2567D
```

Team ID `8N66M2567D` (Patryk Zurek / `smartfrigde`) matches the named Legcord
maintainer. macOS auto-update is signature-gated via Squirrel.Mac, so an
update must carry this same signing identity to install. A sudden change of
signing identity is the signal to pause updates and re-verify.
