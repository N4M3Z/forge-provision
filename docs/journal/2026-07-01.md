# 2026-07-01 — Codex hook ownership

Codex's setup import had copied Claude's global `PreToolUse` hooks into
`~/.codex/hooks.json`. That produced two problems: `dcg` ran twice because it
was already wired natively in `config.toml`, and `rtk hook claude` attempted a
command rewrite through a hook protocol that RTK does not support for Codex.
Codex rejected some rewrites with `updatedInput without
permissionDecision:allow`.

The boundary is now explicit:

- `dcg` remains a native Codex `PreToolUse` hook in `config.toml`.
- RTK uses its supported Codex integration, `rtk init -g --codex`, which adds
  `RTK.md` instructions to `AGENTS.md`; the transparent rewrite hook remains
  Claude-only.
- gbrain remains personal MCP/CLI configuration in the Codex config and
  dotfiles.
- Entire continues to install and own project-local Codex lifecycle hooks.
- forge-cli remains the agents/skills/rules deployment pipeline; harness
  settings and third-party installers stay in forge-provision.

`scripts/configure/codex.sh` now selectively removes imported `rtk hook claude`
and removes imported `dcg` only when native config already contains its
replacement. It preserves unrelated imported hooks. Regression coverage lives
in `tests/test-codex-integrations.sh`.
