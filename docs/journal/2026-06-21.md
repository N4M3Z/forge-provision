# 2026-06-21 Codex as a sandboxed cross-reviewer; Claude settings canonicalized

## What changed

OpenAI Codex joined the machine as an independent second agent for cross-reviewing
Claude Code's work, provisioned to match the existing security posture rather than
sit beside it as a weaker link. Recorded in [PROV-0019][P19]; reference card in
[the codex tldr][TLDR].

- **Install.** `cask "codex"` (CLI) and `cask "codex-app"` (desktop app) in the
  Brewfile. The desktop app carries Computer Use. Auth is interactive (`codex login`).
- **Config.** `manifests/codex/config.toml` is the curated seed; `scripts/configure/codex.sh`
  deploys it only when absent. The live config mirrors the Claude sandbox posture
  where Codex supports it: Seatbelt (`default_permissions = "workspace-local"`),
  a `[permissions.workspace-local.network.domains]` domain allowlist matching
  Claude's `allowedDomains`, workspace roots, a `[shell_environment_policy]` env
  scrub, a read-only `[profiles.review]`, gbrain over MCP, and dcg as a
  `PreToolUse` hook (the same guard Claude runs, now trusted by Codex via a
  recorded hash).
- **Two gaps that don't translate.** Codex has no read-deny (Seatbelt reads stay
  broad) and no static command-exclusion list (commands escalate through
  `approval_policy`; the built-in execpolicy is not user-authored). Documented
  rather than faked.

## Claude settings canonicalized

`~/.claude/settings.json` was cleaned and made canonical in the chezmoi source
(`dot_claude/private_settings.json`): merged the two PreToolUse Bash hook matchers,
dropped a duplicate voice key, pruned disabled plugins, reconciled the stale
forge-provision partial key. The live write is blocked by the self-modification
guard, so it activates on `chezmoi apply`.

## The auto-mode policy correction

A wrong assumption got corrected: auto mode IS configurable with prose. Claude's
auto-mode classifier reads an `autoMode` block (`environment`, `soft_deny`,
`hard_deny`, `allow`) plus CLAUDE.md; Codex routes escalations through
`approvals_reviewer` and reads AGENTS.md. That is the soft, AI-judged policy layer.
The hard layer is structural: `permissions.deny` and dcg's regex packs. An
`autoMode` block encoding sane git practice, credential protection, and the
sandbox boundary now sits in the canonical Claude settings.

## The Computer Use tension

The desktop app's Computer Use drives arbitrary macOS GUI apps via Screen Recording
and Accessibility grants. It runs outside the command sandbox and dcg, so the
config.toml isolation does not constrain what it clicks. It is the highest-trust
capability in the stack and is meant for deliberate, per-session use, not a standing
grant. The sandboxed CLI and the unsandboxed desktop are two different trust levels
wearing the same name.
