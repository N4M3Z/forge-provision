# 2026-07-06 — Codex daily-driver hardening audit

Codex was audited against Claude Code's harness posture before treating it as a
second daily driver.

## Verified state

- `codex doctor` passes: config parses, state DBs are healthy, MCP lists 2
  configured stdio servers plus Computer Use from the plugin, and no MCP startup
  failures are reported.
- The hard sandbox layer is close to Claude: `default_permissions =
  "workspace-local"`, restricted filesystem, limited network, writable project
  roots, and a native `dcg` `PreToolUse` hook.
- `~/.codex/hooks.json` no longer carries the bad Claude `rtk hook claude`
  import; `rtk` is instruction-driven for Codex.
- Live `~/.codex/AGENTS.md` only imported RTK before this audit, leaving Codex
  without the Claude-equivalent auto-mode policy prose.

## Findings

- Claude still has one protection Codex cannot mirror: `sandbox.filesystem.denyRead`
  for credential stores. Codex reads are broad under Seatbelt, so credentials
  must stay out of prompts and tool paths, with `dcg` and human review as the
  guardrails.
- Claude's `autoMode` block maps only approximately: Codex uses
  `approvals_reviewer = "auto_review"` plus AGENTS.md, not a named `autoMode`
  structure.
- `codex doctor` reports mixed auth signals when `OPENAI_API_KEY=ollama` is in
  the global Codex process environment. Keep local-model values scoped to
  `[mcp_servers.gbrain.env]`, not global shell env.
- The recurring `could not create PATH aliases: Operation not permitted` warning
  is a sandboxed startup write attempt, not an MCP failure.
- Skill duplication is real: `~/.codex/skills` and `~/.agents/skills` overlap
  heavily, and some same-named skills differ. For local stability, forge-managed
  Codex skills remain canonical under `~/.codex/skills` until a runtime probe
  proves a migration is required.
- Computer Use is enabled through the desktop plugin. It is useful, but it drives
  GUI apps outside the CLI sandbox and dcg; use it as a deliberate per-session
  capability.

## Durable updates

- `manifests/codex/config.toml` now uses the current `workspace-local` permissions
  model instead of the pre-2026 Codex seed shape.
- `manifests/codex/AGENTS.md` now carries the daily-driver policy prose that
  mirrors Claude's auto-mode stance: safe roots, trusted destinations, git
  operations that require explicit approval, credential boundaries, untrusted
  repo handling, and Computer Use constraints.
- The Codex TLDR and PROV-0019 now document `approvals_reviewer`, the mixed-auth
  warning, PATH-alias warning, and duplicate skill-root hygiene.
- ARCH-0032, the jj TLDR, AGENTS.md, and the Codex TLDR now pin the workspace
  placement convention: parallel jj workspaces belong in the owning repo's
  local ignored `.worktrees/` directory with explicit names. A workspace under
  an unrelated writable harness root or random sibling folder is only a sandbox
  artifact and should be relocated.
