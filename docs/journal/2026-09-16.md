# 2026-09-16: Git signing key from the inserted YubiKey

The global git config carried a `user.signingkey` that no key on this machine
could satisfy. The value had come along from another machine, `git config`
accepted it, and the first signed commit failed with "No secret key". Nothing in
the provisioning run wrote that value, and nothing checked it.

`scripts/configure/gpg-signing.sh` now owns it. The script asks gpg which card
is inserted, reads the fingerprint from that card's signature slot, confirms the
local keyring has a stub for it, and pins git to that subkey with a trailing
`!`. It also sets `gpg.format=openpgp`, `commit.gpgsign=true` and
`tag.gpgsign=true`, the ARCH-0006 default. A machine with several YubiKeys
signs with the one inserted when the script runs. `GIT_SIGNING_KEY` in `.env`
replaces detection for a machine that must use one specific key; the value
still has to resolve to a usable key.

`scripts/verify/signing.sh` closes the gap on the check side. It fails when the
configured key is not one gpg can sign with here, and it reports whether the
card that holds the key is inserted. The colon-format parsing behind both
scripts lives in `scripts/lib/gpg.sh` and is covered by
`tests/test-gpg-signing.sh` with recorded, anonymised gpg output.

The chezmoi-managed jj config keeps its own copy of the signing key and needs
the same correction on the dotfiles side.
