# 2026-06-24 Zed as a command surface: launcher tasks, REPL kernels, capture split

## What changed

The Zed setup grew from "edit markdown" into an agentic command surface, and this
session captured the whole sprawl into version control. The decisions are recorded
in [PROV-0020](../decisions/PROV-0020%20Zed%20editor-as-launcher%20and%20REPL%20kernels.md);
the moving parts:

- **Launcher tasks + leader keymap.** Terminal tools run as Zed tasks under a
  space-leader keymap, opened in a centered pane and also reachable from the
  task-spawn palette: gitui and jjui (the gitui-style jj TUI, preferred over
  lazyjj), a Postgres browser, the review TUI for working-tree / vs-main, a
  markdown pager, shellcheck, gitleaks, and PDF export via pandoc + typst.
- **Env-safe dispatcher.** Commands that need the current file or selection run
  through a small dispatcher invoked with a literal action only; it reads the
  `ZED_*` variables from the environment instead of letting Zed interpolate them
  into a `zsh -i -c` string. This killed a real bug class: a selection containing
  quotes/parens, or a path with spaces, was being re-parsed by the shell.
- **REPL kernels.** `space m r` (`repl::Run`) now backs onto Jupyter kernels for
  Python, TypeScript/JS (Deno), Shell (bash_kernel), and Ruby (iruby); Zed picks
  the kernel from the block's language. One guarded, idempotent script registers
  them. PHP and Rust were considered and skipped, PHP's only kernel is dormant
  on a dead ZeroMQ extension, and Rust's evcxr recompiles every evaluation.
- **PKM via markdown-oxide**, with the brain-recall result formatting reworked
  from a raw chunk dump into a titled, sourced, excerpted list.

## Public / private split

forge-provision is public, so the capture split generic from personal. The public
baseline (`manifests/zed/`, the configure scripts, Brewfile deps, the moxide
config, these docs) carries only generic tooling, no personal wrappers, no
vault-specific tasks, no brain database URL. The complete live config plus the
personal wrapper commands and brain context server live in the dotfiles lane,
captured via chezmoi so a `chezmoi apply` no longer clobbers the tuned config.

## Follow-ups

- Run `scripts/configure/zed-repl-kernel.sh` (after `brew install bash zeromq ruby`)
  to register the kernels; `space m r` is a no-op until then.
- The "type a marker in a note and relay to a running terminal agent" idea stays
  deferred; the live path is sending a selection to the in-editor agent.
