# 2026-06-17 In-sandbox PII redaction for claude-box

## What changed

claude-box gained a redaction variant. The harness running inside the VM routes
through forge-redact (mitmproxy plus Microsoft Presidio) on loopback, so secrets
hard-block and free-form PII is replaced with consistent surrogates before any
request leaves the VM. The host's own Claude is untouched. The decision is recorded
in [VIRT-0003](../decisions/VIRT-0003 In-sandbox PII redaction.md).

The de-anonymization vault is synced host-to-VM so surrogates stay consistent across
runs and reverse cleanly, without the YubiKey-backed private key ever entering the
VM. `redact run` decrypts the master on the host (one touch) into a plaintext seed
mounted read-only at `/seed`; forge-redact loads it (its `vault_seed_path` option),
mints any new values, and writes the updated map to `/capture` encrypted to the
operator's public key (touchless). Because that capture is a superset of the master
and already encrypted to the operator's key, `redact run` promotes it to the master
with a move. The box never decrypts.

While the plaintext seed is in the VM it is guarded by Claude Code's own native
sandbox, baked to `/etc/claude-code/managed-settings.json` the way proton-harness
does it: `denyRead` covers `/seed` and `/capture` so the agent cannot open the map,
an egress allowlist (`sandbox.network.allowedDomains`) bounds where it can connect,
`enableWeakerNestedSandbox` makes it enforce inside the VM, and `failIfUnavailable`
fails closed. That sandbox is what bounds the agent; Apple container cannot run a
network firewall (one network per container, no CAP_NET_ADMIN), so the boundary lives
one layer up in Claude Code rather than in the container network.

## Pieces

- `scripts/sandbox/claude-box/redact.Containerfile`: `FROM claude-box`, adds the
  redaction stack, bakes the policy, the managed-settings sandbox, and the operator
  public key; fails the build if the recipient does not resolve.
- `scripts/sandbox/claude-box/managed-settings.json`: Claude Code's native sandbox,
  the egress allowlist and the `/seed` / `/capture` denyRead.
- `scripts/sandbox/claude-box/redact-entry`: starts the proxy, waits for the CA and
  port, runs the planted-secret self-test (fail closed), sets the routing env, execs.
- `scripts/sandbox/claude-box/redact-policy.yaml`: the box policy, `vault_seed_path`
  at `/seed` and the encrypted vault and log at `/capture`.
- `scripts/sandbox/claude-box/redact`: the `build` / `run` dispatcher. `run` decrypts
  the master into the seed (one YubiKey touch), runs the box, and promotes the captured
  vault back to the master; `build` assembles the image. Driven by `make redact ...`.

forge-redact's `vault_seed_path` (load a host-decrypted vault in a keyless
environment) is what makes the keyless in-VM load possible.
