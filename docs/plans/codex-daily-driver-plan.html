.agents or .codex? open

Recommended split:

  • ~/.agents/skills and repo .agents/skills: canonical Codex skill roots per current Codex docs.
  • ~/.codex/agents and repo .codex/agents: Codex subagents as TOML.
  • ~/.codex/config.toml, ~/.codex/hooks.json, ~/.codex/auth.json: Codex app/CLI state and settings.
  • ~/.claude: Claude settings, agents, hooks, and credentials.

The live machine currently exposes both ~/.codex/skills and ~/.agents/skills, with many same-name divergent skills. The plan is merge first, then archive or disable the duplicate legacy Codex skill copies after backup.

node_repl revised

node_repl is not something you appear to have installed manually. It is a Codex-provided MCP/tool server: a persistent Node-backed JavaScript runtime used by Codex/plugin tooling. The live Codex config contains it because the app/runtime injected it.

Recommendation: preserve it as app-managed state, but do not put it in forge-provision's baseline seed. The configure script should not delete unknown MCP servers when it upserts stable settings.

Config ownership open

The live ~/.codex/config.toml is app-managed after Codex Desktop runs. It carries plugin enablement, trusted hook hashes, project trust, node_repl, model/status preferences, and desktop state. A full chezmoi apply would wipe useful state.

Recommended change: forge-provision should treat manifests/codex/config.toml as a seed or desired fragment. scripts/configure/codex.sh should upsert only stable keys and preserve everything else.

  • Upsert: approval mode, workspace-local permissions, review profile, shell env policy, dcg hook, gbrain MCP env.
  • Remove from global subprocess env: OPENAI_API_KEY=ollama and OPENAI_BASE_URL=http://localhost:11434/v1.
  • Preserve: unknown MCP servers, plugin state, hook trust hashes, project trust, model UI preferences, desktop state.

MCP and gbrain revised

The current "MCP complaints" are not a hard MCP failure. codex doctor sees gbrain, node_repl, and computer-use. The recurring warning is mostly plugin metadata noise plus a mixed-auth note caused by global OpenAI-compatible local-model env vars.

Recommendation: keep gbrain local-model values scoped inside [mcp_servers.gbrain.env]. Do not leak them through [shell_environment_policy.set], where every subprocess inherits them.

Skill cleanup open

The duplicated skill roots are a real daily-driver problem. Codex currently sees duplicate names from ~/.codex/skills and ~/.agents/skills; important skills differ by hash.

Recommended sequence:

  1. Inventory same-name skills and hash differences.
  2. Promote the newer/correct content into canonical ~/.agents/skills.
  3. Keep agent-only or Codex-only skills intentionally, with provenance.
  4. Archive or disable duplicate non-system ~/.codex/skills copies after backup.
  5. Add a doctor/test that fails on same-name divergent skill roots.

Specific content fix: update stale SessionResume/SessionCapture wording so automatic capture means SpecStory plus memsearch via session-sync, while curated manual capture means gbrain.

Capture hooks open

Codex currently has a broken global hook: ~/.codex/hooks.json calls a missing capture-session. The working script is forge-data/scripts/session-sync, which Claude already uses.

Recommended repair:

  • Replace capture-session with session-sync.
  • Use PreCompact and likely Stop for Codex lifecycle capture.
  • Keep hook stdout quiet and exit 0 so capture cannot break normal sessions.
  • Ask before running it manually because it writes to ~/Data and invokes local indexing.

Indexing after capture open

session-sync preserves raw transcripts, but the memsearch indexing phase is noisy: logs show Milvus Lite too_many_pings. That should not run on every lifecycle hook until it is throttled.

Recommendation: split capture from indexing. Hooks should preserve raw/session data quickly; launchd, a cooldown file, or a manual command should run heavier indexing afterward.

HtmlPlan packaging open

The installed HtmlPlan skill references template.html, but both local skill roots only contain SKILL.md. This artifact therefore embeds a minimal compatible renderer directly.

Recommended fix: add the missing template to the skill source, deploy it with the skill, and add a verification check that every skill-referenced relative asset exists.

Recommended sequence open

  1. Patch source docs and manifests first: AGENTS template source, stale Codex TLDR text, HarnessSecurity config keys, and configure-script comments.
  2. Make scripts/configure/codex.sh dry-run aware for Codex upserts and hook repair.
  3. Add tests for broken hook paths, stale config keys, global OpenAI env leakage, and duplicate skill roots.
  4. Only after review, apply live ~/.codex/AGENTS.md and hook repairs.
  5. Run codex doctor, codex mcp list, TOML parse checks, and a controlled session-sync validation with approval.
