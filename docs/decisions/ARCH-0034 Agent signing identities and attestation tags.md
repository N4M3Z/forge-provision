# Agent signing identities and attestation tags

## Context and Problem Statement

Sign-on-push (ARCH-0006, ARCH-0032) signs every unsigned commit at push with the touch-gated YubiKey. Agent-driven pushes therefore block on a physical touch the agent cannot perform: pinentry raises a dialog nobody answers, the push dies with `gpg: signing failed: Timeout`, and unattended flows cannot publish work at all. At the same time, every commit an agent makes carries the human's name, email, and (once pushed) signature, so history cannot answer which harness, model, or machine produced a change.

The two concerns pull apart: agents need a signing path with no human in the loop, and the human signature needs to mean something stronger than "a push happened" without being spent on every working commit.

## Decision Drivers

- The YubiKey touch stays the gate for anything published under the human's identity
- Agent flows must never block on a human action
- History must attribute work to the harness and machine that produced it
- Local verification (`git log --show-signature`, `jj log`) must pass for every signer
- One physical touch should cover a whole batch of human signatures

## Decision Outcome

Three lanes, separated by who holds the key.

**Agent lane.** Each harness signs with its own passphrase-less ed25519 key at `~/.ssh/<harness>` (claude, codex, grok, antigravity, opencode), generated by `scripts/install/agent-signing-keys.sh`. The `harness-run` launcher (dotfiles) layers a per-process `JJ_CONFIG` overlay into every agent session, interactive and automated, carrying the harness identity and key:

| Provider    | user.name   | user.email                        | signing key          |
| ----------- | ----------- | --------------------------------- | -------------------- |
| claude      | Claude Code | claude@noreply.\<hostname\>.local      | `~/.ssh/claude`      |
| codex       | Codex       | codex@noreply.\<hostname\>.local       | `~/.ssh/codex`       |
| grok        | Grok        | grok@noreply.\<hostname\>.local        | `~/.ssh/grok`        |
| antigravity | Antigravity | antigravity@noreply.\<hostname\>.local | `~/.ssh/antigravity` |
| opencode    | OpenCode    | opencode@noreply.\<hostname\>.local    | `~/.ssh/opencode`    |

`signing.behavior = "own"` re-signs agent rewrites automatically; with a soft key that costs nothing. The email domain embeds the lowercased hostname, so a commit names both the harness and the machine. Automated runs additionally stamp a co-author trailer carrying the requested model. `scripts/configure/agent-signing.sh` registers each key and principal in `~/.config/git/allowed_signers`, so local verification passes.

**Human lane.** Unchanged from ARCH-0006: GPG on the YubiKey, `signing.behavior = "drop"`, `git.sign-on-push`. Because agent commits arrive already signed, sign-on-push finds nothing to sign in agent work and only ever touches the human's own commits. The OpenPGP signature slot uses the `cached` touch policy (`scripts/configure/yubikey-touch.sh` reports it): one touch opens a window that covers a batch.

**Attestation lane.** The human signature over agent work moves from merge commits to dated `signed/YYYY-MM-DD` tags (UTC, `.2`/`.3` suffix on same-day repeats). A signed tag covers the full history hash beneath it, so one tag attests everything since the previous one, and the tag trail is an immutable audit log of what was reviewed when. The `sd sign` namespace (PROV-0024 dispatcher; scripts live in dotfiles) drives it: `sd sign check` is a read-only scanner over `~/Agents/N4M3Z` and `~/Developer/N4M3Z` that a launchd agent (`com.n4m3z.sign`, every four hours) runs, posting an alerter notification only when a trunk has moved past its newest `signed/*` tag; `sd sign run` is the interactive batch session, one touch for all pending repos. `scripts/verify/sign.sh` checks the wiring.

### Consequences

- Agent pushes never wait on the YubiKey; unattended flows publish signed, attributed work.
- `.local` committer emails cannot be verified on GitHub, so agent commits carry no Verified badge there; verification is local via allowed_signers. A machine GitHub account holding the agent keys remains possible later if the badge becomes worth five verified addresses.
- The human signature appears only where a touch happened: own commits at push, and `signed/*` tags. Absence of the badge on agent commits is the honest state, not a failure.
- Passphrase-less keys sit on disk; exfiltration lets an attacker sign as an agent identity, not as the human. Keys are cheap to rotate per machine.
- Anyone auditing history reads three signals: author identity (which harness, which machine), commit signature (that harness's key), and the enclosing `signed/*` tag (human reviewed up to here).
